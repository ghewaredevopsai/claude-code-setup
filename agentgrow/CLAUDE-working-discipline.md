# AgentGrow — working discipline (excerpt from CLAUDE.md)

The first section of the production repo's CLAUDE.md, unedited. The rest of the file (code map, feature rules, gotchas) is product-internal.

## Working Discipline
- **Work in a worktree, never in the main checkout**: the main checkout stays on a clean `main`, used only to pull, merge and deploy; parallel sessions share it, so a branch switch or edit there lands in every other session's tree. Start feature work with `git worktree add .claude/worktrees/<name> -b <branch> origin/main` (or the EnterWorktree tool). If you find the main checkout on another branch or holding changes you did not make, leave them alone (no stash, reset or commit) and move to a worktree. `deploy.sh` refuses anything but a clean `main` equal to `origin/main` (`scripts/deploy-preflight.sh`)
- **Verify before assuming**: legacy naming (`payments.razorpay_order_id` holds Cashfree IDs), unit traps (`coupons.value_usd` is cents) and static-export limits (no SSR, no server-side auth) bite often; read Known Gotchas and the schema first
- **State assumptions explicitly** when the task is ambiguous; ask rather than guess. **Surgical edits**: touch only what the task names
- **New route** → the matching `app/routers/<area>.py` (`@router.<method>`); its helpers in `app/services/<area>.py` (infrastructure in `app/*.py`), never in `app/main.py`. Source-grep tests read every backend file via `tests/_source.py::backend_source()`, so assert on `@router.`
- **Verifiable done**: backend `.venv/bin/python -m pytest tests/` (system python has no pytest); frontend `npm run lint && npm run typecheck && npm test && npm run build` (vitest + Testing Library + MSW in `frontend/src/**/*.test.ts[x]`, typed against `api.gen.ts`; never assert on source text); deploys `bash deploy.sh` end-to-end. **No GitHub Actions** (owner, 2026-10-23; `ci.yml` removed): run these yourself, or in a Claude cloud session for work that should run off this machine. `deploy.sh` runs pytest and the frontend build only, so lint, typecheck, `npm test` and the generated-file `--check`s happen only when you run them
- **Real database for SQL changes**: `tests/test_pg_*.py` run `init_db()` and the money path on a real Postgres (`scripts/test-db.sh up`; with `REQUIRE_TEST_PG=1` a missing DB fails rather than skips). Every other test mocks the pool, so a query change only the mocked tests pass is unverified. Fixtures `pg_pool`/`pg_db` in `tests/conftest.py`. Each pytest run creates and drops its own database (`agentgrow_test_r<pid>`) on that server, so parallel sessions and worktrees no longer wipe each other's rows
- **Spec first**: a shipped feature's behaviour is `docs/specs/<feature>.md`, numbered ACs that tests cite (`docs/specs/<feature>.md#ACn`); change an AC and its test together. New features start from `docs/specs/_TEMPLATE.md` in `todo/` (`/spec <slug>`). `tests/test_specs.py` fails on a dangling citation, an uncited AC, a dead `todo/`/`docs/` link, or an Owner-area symbol missing from its file. Rules: `docs/specs/README.md`
- **Typed contracts**: a new or changed route declares its response model in `app/routers/schemas.py` (`response_model=`, a subclass of `Out`, which rejects undeclared keys under the test suite; return a dict, not `JSONResponse`); every client/public JSON route must have one and untyped admin routes may only decrease (`tests/test_api_types.py`); `.venv/bin/python scripts/gen-api-types.py` regenerates `frontend/src/lib/api.gen.ts` (pre-commit hook), called through typed `apiGet()`/`apiSend()` (`frontend/src/lib/apiClient.ts`)
- **Writes go through `db._execute` / `db._execute_returning`, never `db._query`**: `_query` never commits and the pool rolls back a connection returned mid-transaction, so an `UPDATE … RETURNING` via `_query` returns the row and discards it. `test_no_write_statement_goes_through_query` guards it. `docs/knowledge/project_query_writes_never_committed_2026_10_02.md`
- **`deploy.sh` gates on `pytest tests/ -x`**: one failing test blocks every deploy, no skip flag. If failures predate your change, prove it with `git stash`, then fix the stale assertion rather than deselecting it
