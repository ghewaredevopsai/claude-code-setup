1. CLAUDE.md is the guide. Numbers in it are deliberately absent: counts of routes, tables, CronJobs, tests and pages are generated into docs/FACTS.md. Read that, do not count by hand.
2. docs/knowledge/README.md indexes the operational notes (decisions, owner feedback, references) that used to live only in one engineer's Claude memory. Grep it before re-deriving why something is the way it is.
3. Before touching agentcreator/deployer.py deploy(): read docs/agent-deploy-sequence.md (generated, file:line per step). A new _step() needs a description in scripts/gen-deploy-sequence.py or CI fails.
4. Tests: `.venv/bin/python -m pytest tests/ -q -x`. System python has no pytest. SQL or schema change? `scripts/test-db.sh up` first, or the real-database tests (`tests/test_pg_*.py`) skip locally and only CI runs them. The suite is the deploy gate; a failing test blocks deploy.sh. CI on main is advisory only: branch protection is unavailable on this private repo's plan, so a red run does not block a merge. deploy.sh is the gate.
10. Parallel sessions: do feature work in a worktree, never in the main checkout (it stays on a clean main for pull/merge/deploy; another session may be using it). Found it on another branch or with changes you did not make? Leave them and use a worktree. Worktrees live in .claude/worktrees/ (gitignored; .worktreeinclude copies .env in). A worktree has no .venv: run the main checkout's (`"$(git rev-parse --path-format=absolute --git-common-dir)/../.venv/bin/python" -m pytest tests/`), and the pre-commit hook already falls back to it. Each pytest run gets its own test database. deploy.sh takes a machine-wide lock, so a second concurrent deploy exits instead of racing, and refuses to run unless the checkout is a clean main equal to origin/main (scripts/deploy-preflight.sh).
5. One concern per change. Routes live in app/routers/*.py by area; helpers live in app/*.py (db, security, notify, ...) and app/services/<area>.py; callers use them as module attributes (`billing._renewal_pricing(...)`) and tests patch them there, so never import a helper by name. app/main.py only assembles the app.
6. Enable the hooks once per clone: `git config core.hooksPath .githooks`. The hook regenerates docs/FACTS.md and docs/agent-deploy-sequence.md on commit.
7. This repo depends on ~/ai-business-agents for the CRM schema, agent fleet state and the numbered gotchas it cites (#NN). Read that repo's GOTCHAS.md row before acting on a number.
8. CLAUDE.md's "Deploy and infrastructure", "Security" and "Known Gotchas" sections are not optional reading before K8s, Helm, pod-exec, payment or auth work; docs/OPERATIONS.md has the full story behind each.
9. Specs: docs/specs/<feature>.md says what a shipped feature does now, as numbered ACs that tests cite (`docs/specs/<feature>.md#ACn`). Read the spec before changing that feature, and change the AC and its test together. New feature: `/spec <slug>`. tests/test_specs.py fails on a dangling citation, an uncited AC or a dead todo/docs link.
